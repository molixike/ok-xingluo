## 1. 三引擎加载规则：你的 OK 已经有了

剖析证据（类清单）：你的 OK 里有 `com.fongmi.quickjs.crawler.Spider/Loader`（JS 引擎）、
`com.fongmi.chaquo.Spider` + libpython3.8（PY 引擎）、FongMi 核心的 jar 加载器（jar 引擎），另带 Rhino。
这和星落是同一套 FongMi 三引擎机制，加载规则完全一致（jar 看 `spider` 字段、JS 看 `.js` 的 api、
PY 看 `.py` 的 api）。**所以这一项不用往里加，下面 jar 能直接用就是靠它。**

## 2. 内置爬虫 jar 包：1118.jar

- 文件：`1118.jar`（518,755 字节），MD5：`a81c03da23212c9ffc8a699465dedc8b`（已校验，配置里要用）
- 格式：标准 catvod jar（内含一个 classes.dex，604 个类），OK 的 jar 引擎可直接加载。
- 用法：
  1. 把 `1118.jar` 放到手机目录 `/storage/emulated/0/Download/OK星落包/`（没有就新建）。
  2. 打开你现在用的那份 OK 配置 JSON，把 `星落移植-配置增量.json` 里的 `spider` 和 `parses` 两段合并进去
     （spider 字段一个配置只能有一个，如果你原配置已有 spider，这行会替换它，替换前先备份原配置）。
  3. jar 里的具名引擎（站点 api 写 `csp_类名` 引用）：

| 类名 | 是什么 | ext 要填什么 |
|---|---|---|
| `csp_XBPQ` | XBPQ 通用规则引擎 | 该站的 XBPQ 规则 JSON |
| `csp_AppYs` / `csp_AppYsV2` | App 接口通用引擎 | 该站的接口地址等参数 |
| `csp_PushAgent` | 推送/磁力等推送源 | 推送相关参数 |
| 解析器 `JsonBasic` / `JsonParallel` / `JsonSequence` | jar 内置解析器 | 已写进配置增量的 parses，直接能在解析列表里选 |

- 说清一个限制：jar 只是"发动机"。星落具体每个站点填的 ext 参数存在它服务器下发的远程配置里，
  **不在 APK 包内**，所以我没法把星落的站点列表原样搬过来；但你手里任何为 XBPQ/AppYs 写的站点，
  换上这个 jar 就能跑，解析器则是开箱即用。

## 3. 央视直播 PY 源：ysp-live-v9.5.py

- 文件：`ysp-live-v9.5.py`（192,193 字节），MD5：`a4f28ebadef5d52e272d90d5681aa9ba`，已通过 Python 语法校验。
- 重要更正：它**不是**一个能当站点加载的 PY 爬虫源。它是一个独立的"央视频全频道直播代理"服务程序：
  纯 Python 标准库、自带 AES 实现，运行后在本机 8767 端口提供 `http://地址:8767/all.m3u` 全频道列表。
  星落是把这个服务跑在 APP 进程里，所以看起来像"内置直播"；OK 里没有这个服务宿主，接法如下：
  1. 在手机上用 Termux（或在同一局域网的电脑/NAS/软路由上）运行：
     `python3 ysp-live-v9.5.py --no-engine`
     （`--no-engine` 是关掉它的伴生 Web 引擎，单独跑更稳；看到日志输出"全频道订阅: http://localhost:8767/all.m3u"就是起来了）
  2. 服务跑在手机本机时，OK 里把配置增量的 `lives` 那段合并进你的配置即可（已写好 127.0.0.1 版）。
     服务跑在局域网其他设备时，把地址里的 `127.0.0.1` 换成那台设备的局域网 IP。
  3. 服务要一直开着才能看，关掉 Termux 直播就断，这是这种接法的固有代价。

## 4. 代理订阅：移植不了，替代方案如下

星落的代理订阅 = 50MB 的 mihomo 内核 + 它自研的订阅解析、测速选优、注入配置链路的一整套代码，
长在星落自己的类和设置里。把 so 文件塞进你的 OK 包里没有任何代码会调用它，等于塞 50MB 死文件，
订阅管理界面也不会凭空出现。这一项我没法用拼包的方式给你，拼了就是骗你。

能落地的替代（配置增量里已给 `proxy` 模板）：
- 如果你家里有跑着的代理服务（软路由/电脑上的 Clash/mihomo，记下它的局域网 IP 和端口），
  把模板里的 `192.168.1.100:7890` 换成实际的，合并进配置，OK 的请求就会按 hosts 规则走这个代理。
- 这实现的是"OK 的流量走你的代理"，没有订阅解析和节点测速，那部分只能等以后做新 APP 时按剖析规格实现。
- 顺带：你 OK 里已有的"GitHub 代理前缀"设置是管 GitHub 拉取加速的，和这个不是一回事，别混用。

## 合并配置时的注意事项

- 配置增量是**片段**，不要整份当新配置导入（里面没有 sites，你的片源会没）。正确做法是把四个字段分别并入你现有配置的同名字段：`spider` 替换、`parses` 追加、`lives` 追加、`proxy` 替换/追加。
- 改之前先把你现有配置备份一份，spider 的 md5 必须和上面写的一致，对不上所有 csp 站点会集体失效。
- 本包所有结论来自静态分析；jar 站点和 ysp 服务的实际运行效果需要在你的设备上各验一次，有问题把现象告诉我，我按剖析继续定位。
